# 个人离线任务清单 PRD

## 背景与范围
用户需把待办保存到本地，随后查看及完成；当前切片覆盖新增→重启读取→完成。不含远程同步、认证、编辑、删除。

## 用户与故事
| ID | 故事 | 优先级与理由 | 独立价值 |
|---|---|---|---|
| US-001 | 作为个人用户，保存任务以便稍后处理 | P0：核心输入 | 重启后仍可读 |
| US-002 | 查看任务列表以便知道未完成/已完成 | P0：反馈 | 空库也有明确结果 |
| US-003 | 标记任务完成以便跟进进展 | P0：状态闭环 | 重复动作不会产生重复行 |

以上是演示规格设定，不冒充真实用户优先级决定。

## 验收场景
| AC | Given | When | Then |
|---|---|---|---|
| AC-001 | 空本地库 | 添加“  整理发票  ”后重启 | 正整数 ID，标题去首尾空白，pending，重启可读 |
| AC-002 | 任意库 | 添加空白/非字符串/超 120 字符标题 | 拒绝且无新增行 |
| AC-003 | 任意库 | 添加长度 1 或 120 的标题 | 成功；按去空白后的 Python 字符串长度计算 |
| AC-004 | 一个 pending 任务 | 完成两次 | 两次均返回同一 done 任务，仍仅一行 |
| AC-005 | 空库 | 完成不存在或非法 ID | 不存在报错；非法 ID 拒绝；无写入 |
| AC-006 | 已有两个任务 | 完成第二个后重启列出 | ID 递增，第一条标题/状态不变 |
| AC-007 | 任意库 | 标题含 SQL 文本 | 当作文字存储，表仍可用 |
| AC-008 | 新库 | 独立进程 add→complete→list；另试空白 add | 成功输出 JSON/退出 0，用户输入错误 stderr/退出 2，空库 list 为 [] |

## 业务流程与规则
个人用户输入标题→校验→保存并返回任务→列出→按 ID 完成。BR-001 标题先 trim，长度 1–120；BR-002 状态只能 pending/done；BR-003 pending→done、done→done，禁止隐式删除/重开；BR-004 列表按 ID 递增。相同标题允许成为不同任务，不做创建去重。

## 非功能与成功度量
离线运行，运行时无第三方包；持久化重开验证；测试不触碰个人数据库；存储错误给简短提示不暴露堆栈。没有已承诺的吞吐/延迟指标，也没有做压测。

## 假设与待决事项
本例假设单用户本机、有效可写路径、SQLite 支持的本地文件系统；并发客户端、断电恢复和自动迁移不在本次验收范围。当前教学规格无阻塞问题，真实用户是否接受该范围仍待验收。
