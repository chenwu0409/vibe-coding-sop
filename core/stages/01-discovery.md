# L1：从一句话需求得到可实现、可验收的范围

输入：原始诉求、宪法、现有功能与反馈。产出：requirements.md；必要时 research、glossary、wireframe。对应原 SOP 调研、PRD、原型和 Skill 触发清单。

## 先判断不确定性

| 未知项 | 处理方式 | 证据写哪里 |
|---|---|---|
| 代码已有默认行为、配置或命名 | 读代码/测试后复用 | 需求假设或术语映射 |
| 用户要的业务结果、权限边界不明确 | 提出具体问题、候选结果与建议 | 待决问题及实际答复 |
| 第三方能力/接口、技术可行性未知 | 查对应版本官方资料，做最小实验 | research |
| 页面和交互理解不一致 | 先走可点击主流程和状态图 | wireframe |
| 局部实现细节不影响验收 | 在已有约束内合理选择 | design/development |

不要按需求字数或固定盘问轮数决定提问。一次只集中处理当前切片的阻塞问题；其余可延后问题注明影响范围，继续独立工作。

## 调研如何结束

先写“调研要决定什么”，最多选择少量真实候选。比较适用条件、接入成本、失败行为和验证结果。记录官方来源、版本、查阅日期；不把搜索摘要或别人案例当本项目的实测。

最高风险假设优先做小实验。例如外部识别接口：确认认证来源、请求格式、响应字段、超时/限额和一次真实成功请求；401 只能证明收到认证失败响应，不能算业务链路跑通。无真实凭证时用 mock 验证本地契约，并明确实际服务未验证。

## PRD 起草顺序

1. 写背景、用户痛点、当前做法和目标结果；技术实现留给 L2。
2. 覆盖本次功能的参与者：操作者、审核者、被影响者、系统触发者。按“作为…希望…以便…”写核心故事。
3. 给故事分优先级：P0 为本次交付必需，P1 为重要但可后续，P2 为候选；注明价值和优先级依据，业务取舍由负责人确认。
4. 每个 P0 故事写一个正常场景和真正相关的失败/边界场景，以 AC-001 等编号。Given 是前置状态，When 是动作，Then 是外部可观察的结果及副作用。
5. 对核心流程写角色步骤、介入点、输入输出和业务黑盒。黑盒只描述业务判断，例如“已完成任务再次完成仍保持完成”，不写 SQL 或 SDK 调用。
6. 按实际需要写非功能需求：测量对象、运行条件、阈值及验证方法。没有依据的并发量/响应时间只作为待验证假设。
7. 汇总假设、已决定事项、仍阻塞的 NEEDS CLARIFICATION 项；未进入本次范围的功能移入后续清单，不假装已实现。

## 交互决定的确认边界

页面颜色、间距和不影响操作含义的布局细节，Agent 可以在既有设计系统内选择，并把选择记录为低风险假设。会改变用户如何完成任务的交互语义必须进入 AC、wireframe 或需求决定：例如点击与长按的含义、拖动是否立即保存、开始/结束日期如何归一化、删除是否可恢复、错误提示是否阻止提交。未确认时可以做隔离原型或可回退实验，但不能把猜测写成已确认需求，也不能在交付时省略真实操作验收。

## 示例：把“做个待办工具”收敛

先查明是否已有项目和终端要求。若用户确认个人离线 CLI：
- US-001 / P0：作为个人用户，我能保存任务，以便重启后继续处理。
- AC-001：Given 空数据库，When 添加“整理发票”，Then 返回正整数 ID，再启动程序列出同一 ID 与标题。
- AC-002：Given 任意数据库，When 添加空白标题，Then 明确报错且任务数量不变。
- AC-003：Given 一个未完成任务，When 标记完成，Then 列表状态为 done；重复操作不创建新行。
- 暂不做：多人权限、提醒、云同步。若用户需要其中一项，重新评估范围。

反例：“支持新增任务、页面美观、测试通过”缺少具体输入、错误行为和可观察结果。

## 术语与原型（条件触发）

术语：从需求、类/字段、接口、表中找一词多义或同义不同名。记录业务定义、唯一代码名、旧别名、关系与状态。配置和端点只引用权威配置/契约，不把可能过期的地址永久固化在 glossary。

原型：列角色旅程、页面目标、关键元素、操作→反馈→下一状态。至少走通 P0 主流程，并检查 loading/空/错误/无权限/重复提交中适用的状态。标清模拟数据和真实能力，负责人确认交互后回写 AC。品牌和布局复用项目设计系统，不强制原文示例的颜色、页面拆分方式或宽度。

## 内容审查与完成

每个本次核心故事能否独立验证？失败时会写数据、扣资源或调用外部服务吗？体验验收和系统验收是否区分？是否有互相矛盾的规则或尚未决定的业务边界？

如果答案影响当前切片，回到澄清；其余记录到后续范围。完成后把 AC 编号带入技术设计、任务和测试，形成一条追踪链。
